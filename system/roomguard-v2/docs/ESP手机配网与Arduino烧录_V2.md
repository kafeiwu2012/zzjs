# ESP手机配网与Arduino烧录手册 V2.0

## 1. 一个源码体系，两份芯片固件

支持经典ESP32-D0WD系列与ESP8266 NodeMCU。两者不能共用同一个BIN；同型号节点可烧同一份固件，Wi-Fi、房间和设备凭据不编译进程序。设备ID由STA MAC生成，重启后稳定；房间名称由教师后台绑定。

打开arduino/RoomGuard_ESP32/RoomGuard_ESP32.ino或arduino/RoomGuard_ESP8266/RoomGuard_ESP8266.ino。完整setup()/loop()在NodeRuntime.cpp，配网在NetworkPortal.cpp，PortalLite.h为有界非阻塞HTTP处理器。

Arduino IDE2.x将Sketchbook位置设为项目arduino文件夹，重启IDE，libraries内固定版本库随包提供。安装开发板管理器：

```text
https://espressif.github.io/arduino-esp32/package_esp32_index.json
https://arduino.esp8266.com/stable/package_esp8266com_index.json
```

| 目标 | 核心版本 | IDE板型 |
| --- | --- | --- |
| ESP32 | Espressif esp32 2.0.17 | ESP32 Dev Module |
| ESP8266 | ESP8266 Community 3.1.2 | NodeMCU1.0（ESP-12E Module） |

库：AsyncMqttClient0.9.0、AsyncTCP1.1.1、ESPAsyncTCP1.2.2、ArduinoJson6.21.5、DHT1.4.6、Adafruit Unified Sensor1.1.15。两份Arduino工程实编译通过，尚未在用户实物烧录。不要在未验证情况下升级主要核心／库。

## 2. 先核对硬件选项

node_options.h仅放硬件参数，不放网络密码。HARDWARE_PROFILE=0对应原型ESP32 AO上10k/下15k；=1对应V1.1基板参考上20k/下10k。ESP8266仍按56k/10k保护，A0连接器满量程必须实测后填ESP8266_A0_FULL_SCALE。MQ预热默认180秒仅开发值，按器件资料与实测调整。

| 信号 | ESP32 GPIO | ESP8266 GPIO／板标签 |
| --- | --- | --- |
| DHT DATA | 27 | 2／D4，启动需上拉 |
| MQ AO | 34／ADC1 | A0 |
| MQ DO | 26 | 14／D5 |
| 火焰 DO | 25 | 12／D6 |
| 有源蜂鸣器 | 23 | 13／D7 |
| RGB R／G／B | 18／19／21 | 4／5／16（D2／D1／D0） |
| 运行后长按配置键 | 0／BOOT | 0／FLASH |

5V模块信号必须经过相应转换。共用模块不等于两板引脚相同。基板仍是未布线审阅草案，不能直接打板。

## 3. USB烧录

把ESP从基板取下，单独Micro-USB数据线连接电脑；安装实际CP2102或CH340驱动，在设备管理器查COM端口。选择对应工程、板型和端口，Upload Speed建议115200；Flash容量参考4MB，需核验实物。

先“验证”，再“上传”。Connecting停住时ESP32尝试按住BOOT、开始写入后松开；ESP8266按开发板正常FLASH/RST流程重试。避免同时外部5V与USB供电，不能把两种固件互刷。

烧录后打开115200串口监视器，复位，记录设备ID、配置热点SSID和随机热点密码。不要投屏公开密码。新ESP8266文件系统未初始化时，首次配网需在网页明确勾选初始化；这会格式化该Flash文件系统，但不擦除程序。已能挂载的配置不会因普通断网被自动格式化。

## 4. Android5.1手机配置步骤

1. 树莓派教师后台/teacher登录，生成10分钟接入码。教师电脑保持连接比赛路由器。
2. 手机连接串口显示的RG-CONFIG-xxxxxx热点，输入该设备独立随机密码。提示“无法访问互联网”时选择保持连接。
3. 用手机浏览器手动打开http://192.168.4.1，不依赖系统一定自动弹窗，不需要先装APK。
4. 输入比赛路由器2.4GHz SSID、密码、树莓派实际IPv4和教师接入码。服务器地址不带http://，端口按本版固定Web8080/MQTT1883。
5. 点击试连接。手机可能因STA接入改变无线频道而暂时断开，切回比赛Wi-Fi；不要假定手机能同时保持两条Wi-Fi。
6. 教师后台出现待接入设备。核对串口设备ID、芯片型号，填写楼层和房间并批准。
7. ESP每隔约5秒重试接入，批准后获得独立MQTT凭据并保存；MQTT连接成功关闭配置热点。各终端在刷新后自动出现该房间。
8. 拔USB，断电插回已经核验的原型／基板，选择正确供电和电平参考跳帽，再用外部5V上电。等待MQ预热并做真实采集与声光验收。

接入码144位随机、10分钟、绑定一台设备。批准前不会返回MQTT密码。接入码及MQTT凭据通过可信局域网HTTP传输，本版没有端到端TLS，不能用于不可信公网。MAC编号是稳定标识，不是硬件防伪证明，教师必须核对实际设备。

## 5. 重新配置与失败回退

正常断网：保留原配置、本地采集报警继续、自动重连，不自动开一个无密码热点。

需要改Wi-Fi或服务器时：在程序已经运行后长按BOOT/FLASH约5秒，再松开。不要在上电时一直按住，否则可能进入下载模式。热点密码可在私密串口窗口读取，热点最多10分钟自动关闭。

更换服务器或本地凭据丢失时，填写教师新接入码。已有设备使用新码重新申请，教师批准会轮换该设备凭据；无需改源码。停用设备需要教师先重新开放接入，再获取新码配网。

候选网络先试连接，收到有效接入响应或成功MQTT连接后才持久保存。60秒未成功时回退本次修改前的网络配置；首次没有旧配置时仍需重新进入配网。ESP32使用NVS单个JSON配置项保存；ESP8266使用LittleFS临时文件重命名保存。实物掉电、Flash异常和无线失败边界仍需验收。

Wi-Fi密码字段留空表示保留原密码，不表示清除。新增热点现场以有密码的比赛Wi-Fi为准。不支持在网页上自动识别任意接线、远程OTA或任意ESP型号；增加新传感器仍需实现相应驱动和协议。

## 6. 报警不依赖配网服务器

MQTT采用异步传输，配网HTTP按字节预算分次处理，接入TCP连接尝试设置短超时。配网期间主循环继续采集和声光控制。软件结构不等于时延已实测，必须在目标ESP、路由器和手机上测最坏响应，特别是黑洞网络与慢请求。

本版常规上报默认5秒，教师可设5—60秒；离线门限按节点实际生效周期的4倍且至少20秒。DHT采集随常规周期，烟雾／火焰本地判断不随上报周期降速。确认、消音和恢复规则与前版一致。
