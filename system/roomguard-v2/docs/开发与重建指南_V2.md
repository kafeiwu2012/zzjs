# 开发与重建指南 V2.0

先运行交付程序并完成实机验收，再修改代码。本文面向继续开发的教师与学生；初次部署优先读《树莓派新手部署与维护_V2》。编译成功只证明构建成功，不证明传感器、电气或手机后台通过。

## 1. 工程入口与修改位置

| 目录／文件 | 用途 |
| --- | --- |
| arduino/RoomGuard_ESP32 | ESP32 Arduino IDE工程，.ino入口与运行逻辑 |
| arduino/RoomGuard_ESP8266 | ESP8266 Arduino IDE工程，与ESP32共享同一业务源码逻辑 |
| arduino/libraries | 随包固定版本第三方库，附上游许可 |
| server/core.py | 数据校验、告警记录、在线判断、参数与存储 |
| server/registry.py | 接入码、设备生命周期、角色、终端和显示方案 |
| server/app.py | HTTP/API、MQTT桥接与后台任务 |
| server/management.py | 维护请求与一致性备份 |
| server/static | 网页工作台、大屏和教师界面，保持ES5兼容旧手机 |
| deploy | Pi首次安装、升级、服务配置和受限root助手 |
| clients/android | Android API22+原生WebView与后台告警服务 |
| clients/windows | Windows10 x64连接器，使用系统Edge独立应用窗口 |
| hardware | 电气参考、BOM、网络表、KiCad未布线草案 |
| tests、tools | 软件测试、模拟演示、诊断、构建与打包辅助 |
| artifacts | 已构建APK／EXE／芯片BIN、编译日志和测试证据 |
| presentation | 24页可编辑PPT、PDF、逐页备注、生成源码 |

NodeRuntime.cpp、NetworkPortal.cpp/.h、PortalLite.h与alarm.h在两个Arduino工程保持一致；node_options.h处理各芯片引脚与量程。修改公共逻辑后同步两份并分别编译，不只修改其中一份。测试用firmware/include/alarm.h也应同步；该目录不是另一套PlatformIO工程。

## 2. 在电脑上运行模拟系统

推荐Python3.11或3.12。以下命令在项目根目录执行，首次需要联网安装依赖。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r server/requirements.txt
python -m tools.run_demo
```

Windows PowerShell可用`py -m venv .venv`创建，然后执行`.venv\Scripts\Activate.ps1`；若本机策略不允许激活，可直接运行`.venv\Scripts\python.exe`。

浏览器访问http://127.0.0.1:8080，教师账号admin／DemoOnly-123456。DEMO明确标识三模拟节点，不修改真实系统账号或服务。初次操作后会在本地生成demo-data-v2，其中有数据库；不放进公共交付包。重新演示可关闭程序后改用新的DATA_DIR，避免重复绑定房间。

局域网实物运行使用Pi安装服务。生产环境不能设置DEMO=1或TEST_HELPER=1，否则账号发放与维护会变为模拟；不要把电脑模拟服务当生产服务器。

## 3. 软件回归

在已创建的虚拟环境安装测试依赖，仍在项目根目录执行：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

包含旧协议回归与V2新装空清单测试，临时数据库由测试夹具创建。现有记录为21项通过；不要将该数字当作以后修改后的固定通过承诺。

C++本地告警状态机测试需要g++：

```bash
g++ -std=c++17 -Wall -Wextra -pedantic tests/alarm_test.cpp -o alarm-check
./alarm-check
```

无输出且退出码0表示断言通过。它不模拟真实ADC、电磁噪声或无线网络。

MQTT集成测试要求本机安装Mosquitto，18885、8891端口空闲：

```bash
python tools/mqtt_v2.py
```

MOSQUITTO_BIN可指定测试代理路径。测试使用临时账号文件、模拟的教师凭据助手与三个软件节点；真实Broker验证ACL与消息链路，但不执行Pi的root助手。部分Mosquitto构建要求哈希账号文件；本脚本的临时明文密码格式适用于交付记录中NO_TLS测试构建，如发行版拒绝，应先按其工具生成测试账号，不能据此改成生产匿名访问。

浏览器测试需要本机Chromium和playwright Python库，启动全新DEMO后运行`python tools/browser_v2.py`。CHROMIUM_BIN可指定浏览器路径（默认/usr/bin/chromium）；脚本会操作并修改模拟数据库，要求初始三节点、104房间未占用。它验证第四节点批准、轮播、方案分发、标签转义和375px布局，不是OPPO真机测试。

## 4. Arduino重建

按烧录手册安装Arduino IDE2.x与固定核心。IDE选择ESP32 Dev Module／核心2.0.17或NodeMCU1.0／核心3.1.2，Sketchbook设为项目arduino目录；分别打开相应.ino验证和上传。不要升级库后直接沿用旧编译结果。

Arduino CLI等价命令（CLI须已配置该arduino目录作为Sketchbook并装好核心）：

```bash
arduino-cli compile --fqbn esp32:esp32:esp32 --output-dir artifacts/esp32 arduino/RoomGuard_ESP32
arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 --output-dir artifacts/esp8266 arduino/RoomGuard_ESP8266
```

首次推荐通过Arduino IDE上传源码，IDE自动选择对应分区与烧录参数；不要把单个应用BIN当成任意地址的整片Flash镜像。编译产物不包含指定房间和Wi-Fi密码；烧录后按手册手机配网并由教师批准。

## 5. Windows EXE重建

Windows10安装Zig0.13并放进PATH，进入clients/windows，在PowerShell运行：

```powershell
.\build.ps1
```

生成RoomGuard.exe。它是本地连接器，通过已安装Edge的独立窗口打开服务器界面，不内置完整浏览器、不提供关闭后的后台告警服务；所有节点、主题与数据来自Pi。交付EXE是x64 GUI交叉构建产物，未执行Windows真机验证。

## 6. Android APK重建

推荐Linux／WSL安装JDK17、Android SDK Platform35、Build Tools35.0.0及Python3；将ANDROID_HOME指向自己的SDK目录，然后在项目根目录执行：

```bash
bash clients/android/build-cli.sh
```

生成artifacts/RoomGuard-Android5.1.apk，minSdk22、targetSdk28、versionName2.0。脚本会在本机build目录生成开发测试签名；同一环境后续构建可保留该私钥以维持覆盖安装，不能公开或打包私钥。正式发布请改为自己的受保护签名流程。交付APK使用本次新测试签名，旧版可能需卸载再安装。

也可在Android Studio导入clients/android，安装Gradle对应依赖后构建；未附Gradle Wrapper或整套SDK缓存。APK的AlertService提供原生后台轮询与声音，网页后台不保证执行；OPPO省电、锁屏Wi-Fi、后台启动仍需实测。

## 7. PPT与文档重建

在项目根目录执行：

```bash
python presentation/build_v2_ppt.py
python tools/export_docs_v2.py
```

先提供artifacts中V2截图。PPT生成器会覆盖同名PPT和逐页讲稿JSON；如果已手工改学校、姓名、图片或备注，先另存备份。Word／PDF生成器从docs内*_V2.md生成同名文件。PDF可用LibreOffice导出PPT，注意字体替代与隐藏备页是否导出。

## 8. 扩展与版本控制

新增同类节点不改网页与服务常量，走接入码→手机配网→教师批准→终端拉取。增加新型号传感器需要定义能力、驱动、状态校验、页面字段及故障语义，不能只填写一个名称就自动支持。

修改协议时保持三方一致：固件上报、服务校验／数据库、终端展示。配置同步核对部署epoch、版本和实际参数；不得仅比较版本号。房间迁移保留采样当时的位置，消音不替代异常恢复，单调计时不受校时影响。

运行`python tools/package_release_v2.py`可重打包。打包器排除密钥、运行数据库、环境文件、build与工具链缓存，输出SHA256和ZIP完整性检查；仍应检查截图与文档是否泄露个人信息。基板需先补测排距、尺寸、脚序和孔位，再完成走线、ERC／DRC和实物验证，不从当前草案直接下单。
