# 双人演讲与教师排练手册 V2.0

PPT共24页：20页主讲、4页隐藏答辩备页，主讲与演示约10—12分钟，实际以排练计时和赛程为准。每页备注含讲稿与操作提示，PPT加入手动淡入切页，不自动跳页。主要文字和图形可编辑，截图是图片。

## 角色与准备

A同学负责硬件操作：识别五类模块、供电与电平核验、Arduino烧录、手机配网、观察声光与执行断网恢复。B同学负责展示：解释背景痛点、数据链路、报警含义和教师管理，给清晰操作口令后再让A动作。教师负责全局账号、接入批准和现场安全安排。

封面学校与姓名需要填写。界面截图为实际软件的模拟数据，已在讲稿说明；实机测试完成后再替换截图和验证页，不把编译当作实测。新增第三节点的实物尚未确认，只有两个节点时可以展示两实体加明确标识的模拟扩展证据。

## 演示口令卡

1. B：“请看两个房间在线，数据分别归属。” A指认实体与页面。
2. B：“请触发101测试异常。” A用已排练的受控方式触发；B指出原因、本地声光及终端变化。
3. B：“确认只是已阅，现在本次消音。” A观察红灯保留；需要时演示新原因重新鸣叫。
4. 扩展场景：有第三实体时，A手机连ESP热点输入接入码；教师核对ID并批准；B指出新卡片自动出现。否则明确使用模拟场景或测试日志。
5. 断网场景：保持ESP供电，使用事先验证可阻断局域网MQTT的方式；B解释本地报警继续与中心离线。路由器“禁止上网”可能不阻断局域网，不能直接当作断网成功。
6. 结束恢复网络和测试输入，等待稳定解除。服务停止等维护操作建议只在专门演示环境完成，不能在没有SSH备用入口时停掉唯一业务服务。

每个场景都按“口令→动作→观察→解释”配合；等待回执时准确说“正在等待确认”，不提前说成功。数字测试输入证明软件链路，不代替物理火焰或气体检出；传感器测试方式由教师按场地条件确定。

## 三轮排练

第一轮理解：两名同学都能说明温湿度不报警、烟雾或火焰触发、确认／消音／解除、断网边界、两种芯片不能共用BIN。

第二轮操作：A完成实测与接入步骤，B根据真实状态讲解；记录故障、修改与复测，而不是只背台词。教师核对模块电平、预热、GPIO2启动、Wi-Fi切换、回执与备份。

第三轮计时：按赛程选择扩展或断网的重点，准备失败备用讲解和截图。学生按实际分工说明自己的理解、装配、配置、调试、修改和测试；不能把辅助工具生成的全部代码表述为学生独立编写。

## 常见答辩问题

- 为什么做？——针对房间分散、巡查有间隔、定位与维护信息不清晰，增加持续感知与就近提醒。
- 为什么不把所有判断放树莓派？——本地报警不能依赖服务器或网络。
- 同一固件能烧两种ESP吗？——公共源码可以复用，二进制必须分别编译；同型号节点使用通用固件后再配网。
- 新设备怎样防止随便接入？——独立热点密码、有时效接入码、教师核对批准和独立MQTT凭据；本版仍只面向可信局域网。
- 教师后台是不是万能控制台？——不是，只提供指定服务和受控维护，底层故障保留SSH。
- 手机锁屏是否保证？——需要原生APK、网络与系统许可，还要在指定OPPO真机测试。
- 有没有真实效果数据？——按已执行测试报告回答，不虚构事故降低率、成本节省或大规模部署成绩。
- 基板能打板了吗？——没有；针距已知，排距和模块尺寸待核验，仍是未布线草案。
- 后续怎样扩展？——先整机验收，再做断网事件缓存、RTC与容量及安全测试。
