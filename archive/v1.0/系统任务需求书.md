# 楼宇房间环境监测与异常声光告警系统
## 系统任务需求书

版本：V1.0（比赛首版需求基线）  
编制日期：2026年11月7日  
文档性质：用于硬件设计、软件开发、装配调试、交付和验收。本次仅形成需求书，不构成开始实施或生成程序的指令。

## 1. 项目目标与范围

设计并装配一套在局域网独立运行的房间环境监测与异常声光告警系统。房间节点独立采集、判断并报警，树莓派负责数据接入、存储、分析、管理和多终端分发。

首版固定范围：两个房间节点、一台树莓派、一台路由器，以及监控大屏、电脑管理、手机管理三个网页使用场景；同时交付 Windows 10 上位机 EXE 和 Android APK。平板通过响应式网页访问。不要求五套独立业务系统，各客户端使用同一服务和数据源。

核心展示能力：多节点定位、并发上报、独立告警、双房间同时告警、断网本地报警、服务器离线识别、重连恢复、多终端同步及历史追溯。

首版不包含公网远程访问、短信、电话、云推送、完整断网采样补传、消防联动或商用消防认证。本系统定位为比赛教学演示原型。

## 3. 系统结构与实现约束

数据路径：传感器→ESP节点→Wi-Fi路由器→树莓派→网页／Windows EXE／Android APK。

控制路径：管理员→树莓派鉴权与记录→指定节点→节点执行并回执→终端更新状态。

推荐首版技术基线：MQTT承担节点遥测、事件、控制与回执；树莓派部署轻量消息代理、业务服务和SQLite数据库；网页通过HTTP接口及WebSocket接收更新，旧浏览器必要时采用轮询降级。最终技术版本需验证ARM64、树莓派3B资源和Android 5.1兼容性。

节点本地采集、判断、LED和蜂鸣器控制必须独立于网络。网络连接和重连不得长期阻塞采集任务。服务器与节点采用一致的告警含义，在线告警以节点上报的实际状态为依据，服务器不得在消音后擅自恢复该次蜂鸣。

## 4. 硬件接口与电气要求

### 4.1 DHT11

采集温度和相对湿度，仅展示和存储，不触发环境异常声光报警。数据口是带专用时序的单总线数字接口，不是普通开关输出。优先3.3V供电，核对模块上拉接法。采样周期采用5秒，读取失败显示“采集故障”；可保留最后有效值但必须附时间及过期标记，不得以0代替故障值。

### 4.2 MQ-2

采用合适的5V电源供电，允许独立电源，必须与ESP信号地共地。供电预算包含加热器持续电流、Wi-Fi峰值及其他模块负载，不得由GPIO供电。

首版采用AO读取烟雾／气体相对响应趋势，DO判断阈值异常。MQ-2对多种气体有响应，未经标准气体标定不得输出声称准确的ppm浓度；界面使用“烟雾／气体相对响应值”和“阈值状态”。DO阈值由模块电位器调整，不能把网页设置误称为已远程改变硬件阈值。

AO、DO均按可能达到5V进行保护设计。必须交付两种ESP各自的参考电路，标出电阻数值、容差、转换方式、输入输出范围、共地、供电和引脚。AO采用计算并留有余量的分压／缓冲方案；DO采用合适的电平转换或经核验的分压方案，不得仅依靠软件限制电压。ESP8266芯片ADC与开发板A0量程可能不同，必须核验板载分压；ESP32模拟采集应选ADC1可用引脚，避免Wi-Fi与ADC2冲突。软件分别配置ADC量程、分辨率及转换比例，不直接比较两板原始ADC计数。

MQ-2首次老化与每次开机稳定时间按实际器件资料和测试确定，参数写入调试记录。未满足预热条件时显示“预热中”，不声称烟雾监测正常；火焰检测仍可工作。不得把任意固定预热秒数作为器件已稳定的证明。

### 4.3 火焰传感器

以最终实物为准，当前按三针VCC、GND、DO数字模块规划，优先3.3V供电。触发有效电平需实测确认并可配置。其结果表示检测到相应红外信号，不能推断火焰温度或实际火灾规模；调试需考虑阳光和其他红外源干扰。

### 4.4 有源蜂鸣器与RGB LED

蜂鸣器确定为低电平触发。5V模块必须核验其输入上拉、驱动结构和3.3V关断兼容性，必要时增加隔离驱动；启动、复位期间应避免误鸣。软件控制鸣叫节奏，不需要生成无源蜂鸣器音频驱动。

RGB按带限流电阻、公共端GND的共阴极模块暂定，实物核验后确定。正常监测显示绿色；环境异常红色闪烁；未告警的预热／采集故障采用黄色提示；未告警的网络断开采用蓝色提示。显示优先级为环境异常＞采集／预热状态＞网络状态＞正常。环境异常时网络故障不能覆盖红色告警。

ESP8266须在正式接线前核算GPIO数量及启动绑带引脚，预留烧录与串口调试能力。确有引脚不足时采用经过确认的I/O扩展，不以不稳定启动接法凑齐。交付完整BOM、引脚表、供电预算、接线图及电平转换参考电路；所有值以核验实物后定稿为准。

## 5. 采集、通信与在线检测

每节点每5秒上报一次完整状态，包含设备编号、房间、启动标识、序号、运行时间、温湿度及有效性、MQ响应及预热状态、烟雾DO状态、火焰状态、网络状态、当前告警、消音状态及配置版本。

告警发生、原因新增／移除和恢复应立即上报，不等待下一次周期。建议本地数字异常识别不超过1秒，不含传感器自身响应时间；在网络正常时，从节点确认异常到在线终端展示目标不超过2秒。

服务器仅以已认证、字段有效的新消息更新最后在线时间。连续20秒未收到有效消息判离线，目标显示窗口20—25秒。可利用MQTT遗嘱加快检测，但不能只依赖遗嘱。重连后节点立即上报当前完整状态，终端恢复在线。

消息可能重复或乱序，须通过设备、启动标识、序号和事件编号去重，避免重复创建告警。遥测历史由数据库保存，不依赖MQTT保留消息。控制消息不得作为会在重连后自动执行的保留指令。

## 6. 报警规则与生命周期

烟雾或火焰任一有效触发，即启动对应房间声光报警；两者同时触发时显示两个原因。两个房间互相独立，能够同时告警。温湿度值及其越界不触发环境报警。

采用短时滤波抑制抖动，不能用较长确认延时掩盖异常。只要仍有任一原因有效，环境告警持续。所有原因恢复后开始正常稳定计时，期间任一原因再次出现则重新计时。

自动解除稳定时间默认10秒，管理员可设置1—300秒；界面标明单位和影响范围。参数下发节点并在节点持久保存，断网仍使用最后生效值。显示期望版本、已生效版本和待同步状态，不能把服务器保存成功等同于节点已生效。

报警状态至少区分：未告警、正在告警、恢复稳定计时、已恢复；确认和消音作为独立属性。管理员确认只记录已阅，不清除异常；消音仅关闭蜂鸣器，LED和界面继续告警。

消音只作用于指定节点当前告警事件。当前原因持续且未新增时保持消音；新增原因重新鸣叫；完全恢复后再触发建立新事件并重新鸣叫。节点重启清除临时消音，传感器有效异常时重新报警。故障导致数据无效不得被视为已恢复：已有异常且对应监测失效时保持未解除并提示故障。

离线不是正常，也不是环境报警已解除。显示“离线”及最后有效时间、最后已知异常；历史值明确标记过期。

## 7. 远程操作、权限与审计

大屏只读，可展示环境状态和播放终端告警声音；电脑、手机、平板管理页面登录后具备相同业务权限。首版至少提供管理员与只读访问边界，默认账户首次使用必须设置密码，接口均执行服务端鉴权，不仅隐藏按钮。

管理员可查看历史、确认告警、对当前事件消音、修改解除时间、导出CSV及校时。所有敏感操作记录操作者、目标、时间、参数及结果。密码不得明文保存，节点使用独立接入凭据；网页不得获得MQTT管理员密钥。

消音和配置指令具有唯一ID、目标、事件ID或版本、有效期及执行回执。消音默认有效期10秒，离线拒绝即时消音且不排队补执行；无回执显示“未确认”，不得显示成功。重复指令需幂等处理。

配置允许保留期望值并在重连后同步；节点确认应用后标记生效。网页声音开关仅影响该终端，不等同于房间蜂鸣器消音。

## 8. 网页、Windows与Android客户端

### 8.1 统一展示与交互

采用一致的专业视觉风格、状态颜色、单位和文字，避免仅依赖颜色表达异常。包含双房间总览、房间详情、在线与最后更新时间、温湿度、烟雾响应、火焰状态、当前告警原因、确认／消音状态、历史曲线和记录查询。

大屏突出房间定位及异常；管理端提供操作与配置；移动端适配竖屏、触控和小屏。至少验证1920×1080、1366×768、平板横竖屏及OPPO R7sm实际屏幕。旧浏览器功能不足时提供兼容实现或清晰提示，不能出现空白页面。

历史支持按房间、时间、事件类型过滤；曲线支持常用时间窗口和适量聚合，避免一次加载全部原始数据。状态变化不需手动刷新。服务器连接中断时，客户端明确提示连接中断，不继续显示为实时正常。

### 8.2 网页声音

提供“启用声音”按钮及声音测试，显示是否启用，遵守浏览器自动播放限制。活跃未消音告警可播放提示；管理员确认不自动等同于关闭所有终端声音。终端本地声音控制不改变节点状态。

网页前台需实时告警；网页在锁屏或后台的声音不作为可保证能力，该要求由APK专门实现。大屏只读访问不能泄露管理凭据。

### 8.3 Windows EXE

支持Windows 10，提供版本信息、服务器地址配置、连接状态及专业界面。允许复用网页业务界面，但必须交付实际可运行EXE和所需运行环境说明，不能仅交付源码或网页链接。嵌入浏览器方案须验证Windows 10目标环境，声明外部运行时依赖。首版不要求Windows程序关闭后继续后台报警。

### 8.4 Android APK与后台告警

兼容Android 5.1（API 22），以OPPO R7sm真机作为验收设备。APK提供前台完整业务展示，并通过原生后台服务维持局域网告警连接、发布通知和播放声音，不能仅用WebView包装代替后台实现。

交付后台运行、省电白名单、锁屏Wi-Fi等必要设置说明，处理断线重连及重复事件。运行条件为：手机能够访问树莓派、Wi-Fi未中断、应用未被强行停止且系统允许后台运行。不得承诺在系统强杀、断网或关机后仍可收到新告警。

验收包括前台、切后台、锁屏至少30分钟后新告警响铃。提示通知应能进入对应房间告警详情；Android前后台服务机制按5.1实际API实现，不使用仅新版本支持的接口。签名APK必须可安装，签名材料不写入公开源码。

## 9. 数据存储、曲线与导出

默认常规采样保留30天，告警、原因变化、确认、消音、恢复、上下线及管理审计保留180天。管理员可调整保留期，清理前提供说明，支持CSV导出；到期自动清理并记录结果。

按双节点5秒周期约每天34560条常规记录进行容量设计。曲线查询按时间窗口限制返回点数，数据写入采用轻量事务和合理索引。监测磁盘剩余空间，不能因磁盘满而无提示停止服务。

CSV包含房间、设备、时间及时区、指标、单位、数据有效性或事件信息；使用兼容中文Excel的编码，处理可能被表格软件解释为公式的文本。故障值用空值及状态表示，不填伪造的正常值。

首版默认断网期间不补传完整采样和事件；重连仅上报当前状态。因此断网期间发生并已恢复的异常可能不进入服务器历史。此限制必须写入操作说明，不能宣称完整追溯；节点持续本地报警能力不受影响。后续可扩展有界事件缓存，不列入首版验收。

## 10. 校时、恢复与运维

树莓派时区在部署时显式配置，中文比赛场景默认Asia/Shanghai；数据库建议保存UTC，终端按指定时区展示。管理员可手动校时或一键采用当前终端时间，操作需二次确认并审计。时间未可信时明确标记，不能将错误日期记录表现为已校准时间。

联网时支持网络校时。预设手机热点仅作为备用校时和维护方式，默认不自动离开比赛路由器；切换会影响原局域网访问，操作说明必须写明。首版不强制增加RTC，若要求断电后始终独立保持准确时钟，可作为后续硬件扩展。

离线超时、正常稳定时间和指令有效期采用单调计时，系统校时不应引发误离线或误解除。记录服务器接收时间与节点运行时间；节点无可信绝对时间时不得伪造精确采集日期。

树莓派断电重启后，消息代理、业务和网页服务自动启动；部署稳定后目标120秒内可访问。节点启动后自动采集、联网、重连，MQ-2重新进入预热状态。提供日志、状态检查、数据库备份与恢复方法，日志轮转限制磁盘使用。供电中断后需验证数据库一致性与未完成告警状态恢复。

## 11. 冲突诊断与统一处理

| 冲突或风险 | 首版统一结论 |
| --- | --- |
| 两个ESP型号不同 | 分别编译和配置，统一通信协议及业务行为，不照搬引脚或ADC参数 |
| 断网要求补传，同时允许只报当前状态 | 以明确的首版简化条款为准：不补传，仅重连报当前；明确历史缺口 |
| 远程消音与持续异常报警 | 允许本次事件蜂鸣器消音，视觉报警持续；新增原因及新事件重新鸣叫 |
| 后台网页响铃与旧安卓限制 | 网页保证前台；APK负责后台并以指定真机验收，列明网络和系统运行条件 |
| 5V模块与3.3V ESP | 硬件完成电平适配，软件同步对应量程与极性；无实物核验不固定电阻值 |
| MQ-2预热与系统正常绿灯 | 预热独立显示，不宣称烟雾检测正常；火焰监测保持运行 |
| 故障或离线与正常恢复 | 故障值不当作正常值，离线保留最后已知异常，不自动清除 |
| 解除时间可配置与断网独立 | 参数下发并持久保存到节点，未回执不视为生效 |
| 手机热点校时与原局域网访问 | 比赛路由器为主，热点手动维护使用，不自动切换 |
| 温湿度故障与温湿度不报警 | 故障作为设备健康提示，不触发环境声光报警；其他传感器继续工作 |

## 12. 交付物及开发顺序
