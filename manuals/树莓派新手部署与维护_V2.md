# 树莓派新手配置与系统维护手册（V2.0）

适用：Raspberry Pi3 Model B、Raspberry Pi OS Lite64-bit、MW305R路由器、Windows10电脑。目标是从空白存储卡到可访问系统，再完成日常维护。无需树莓派桌面，不需要先学会全部Linux命令。

## 0. 先看清操作在哪里进行

| 标记 | 操作位置 | 怎么打开 |
| --- | --- | --- |
| Windows电脑 | PowerShell、浏览器、设备管理器、Arduino IDE | 开始菜单搜索对应程序 |
| 树莓派命令行 | 通过SSH登录后的窗口 | 提示符通常含student@roomguard-pi |
| 路由器管理页 | 电脑浏览器 | 地址以路由器标签／当前网关为准 |

命令代码块不带$或#提示符，可逐行复制；说明中的用户名和IP要替换成自己核验的值。输入Linux密码时通常没有星号，这是正常现象，输入后按回车。Ctrl+C停止前台命令，Ctrl+L清屏，Tab可补全路径。`sudo`表示这条命令需要管理员权限，不要给每个命令都随意加sudo。

本手册统一示例：用户名student、主机名roomguard-pi、项目目录`~/roomguard/roomguard-v2`、树莓派示例地址192.168.1.103。示例地址不是预设保证地址。`~`是当前用户主目录，`pwd`显示当前位置，`ls`列目录，`cd`切目录。

## 1. 准备清单

树莓派3B及可靠5V/2.5A电源；建议32GB或以上可靠MicroSD卡及读卡器；Windows10电脑；路由器；网线；两块ESP及数据线；两套模块、电平适配与节点独立5V电源。树莓派不要从ESP电源口取电，MQ-2也不能从GPIO取电。

安装依赖和开发板包时需要联网；安装完成后的采集、展示与告警可以不依赖互联网。优先让树莓派以网线接比赛路由器LAN口，电脑和手机接同一路由器，ESP接2.4GHz Wi-Fi。

先下载：Raspberry Pi Imager（树莓派官方）、V2.0完整项目ZIP、Arduino IDE2.x。官方地址：https://www.raspberrypi.com/software/ 和 https://www.arduino.cc/en/software 。不要使用来历不明的系统镜像或驱动包。

## 2. Windows电脑：写入系统卡

1. 插入MicroSD读卡器，备份卡内资料。写入会清空选定存储卡，务必选对目标，不要误选电脑硬盘。
2. 打开Imager，选择设备Raspberry Pi3；操作系统选择Raspberry Pi OS（other）中的Raspberry Pi OS Lite（64-bit），不选桌面版。
3. 选卡后进入系统自定义设置：主机名roomguard-pi；自行创建用户名与强密码（示例student）；启用SSH，可采用密码登录或自己已有的SSH公钥。
4. 需要Wi-Fi时预填2.4GHz SSID与密码，无线国家／地区选择实际所在地；时区按实际地点（国内可Asia/Shanghai）。用户名和密码自行保管，不在聊天、投屏或公共文档中填写。
5. 写入并校验成功后安全弹出。树莓派断电插卡，连接网线，再接电源。首次启动等待约3—5分钟。

预期：路由器设备列表出现树莓派。若没有，查卡是否写入成功、网线／无线配置、电源与指示灯，不立即反复重刷。

## 3. 找IP并首次SSH登录

路由器管理页查看已连接设备，找到roomguard-pi或对应MAC，记录IP。电脑必须位于同一可互访局域网，关闭访客隔离／AP隔离。路由器后台密码不等于Wi-Fi密码。

Windows PowerShell（以下IP替换为实际值）：

```powershell
ping 192.168.1.103
ssh student@192.168.1.103
```

首次SSH可能询问主机指纹。确认这是你刚写入并在路由器核对的树莓派，再输入yes，按提示输入自己设定的用户密码。若DNS可用，也可尝试`ssh student@roomguard-pi.local`，失败则仍用路由器查到的IP。

成功后提示符应包含student@roomguard-pi。运行：

```bash
whoami
hostname
uname -m
python3 --version
hostname -I
pwd
```

预期：用户名和主机名符合设置；架构aarch64；Python建议3.11或以上。若是armv7l，应重新核对是否误装32位系统。不要使用老教程默认pi/raspberry账号密码。

常见故障：Connection timed out多为网络／IP／隔离；Connection refused检查SSH是否启用；Permission denied检查用户名、密码和键盘布局。重新刷卡后主机指纹可能变化，先确认确实重刷了自己的设备，再用`ssh-keygen -R 实际IP`删除旧指纹，不能对陌生主机的警告直接忽略。

## 4. 树莓派：检查网络与安装阶段的互联网

```bash
ip route
ping -c 4 192.168.1.1
getent hosts pypi.org
```

路由器网关若不是192.168.1.1，换成`ip route`里default via后的地址。ping网关验证局域网，域名解析与后续apt/pip验证安装所需互联网；二者不是一回事。

若比赛路由器没有互联网，安装阶段可临时接入有互联网的网络。通过SSH切换Wi-Fi会导致会话断开，必须在新网络重新查IP再连接。Raspberry Pi OS较新版本通常用NetworkManager：

```bash
nmcli device status
nmcli device wifi list
sudo nmcli --ask device wifi connect "你要接入的无线名称"
```

`--ask`交互输入密码，避免把无线密码写在命令历史。手机热点作为维护备用时需兼容2.4GHz；安装结束切回比赛路由器，再重新确认树莓派IP，修改ESP及终端服务器地址。不要以为热点地址与比赛网段相同。条件允许时在安装阶段直接让比赛路由器具备互联网，步骤最少。

## 5. 树莓派：校时与基础工具

系统时间错误可能造成HTTPS下载和历史记录错误。先看：

```bash
date
timedatectl status
sudo timedatectl set-timezone Asia/Shanghai
sudo timedatectl set-ntp true
```

时区按实际地区调整。没有互联网时，可先手动设置当前实际日期时间，不要照抄旧示例日期：

```bash
sudo timedatectl set-ntp false
sudo date -s "YYYY-MM-DD HH:MM:SS"
```

把YYYY等替换为当前值，系统部署完成后也可在管理网页一键校时。

基础更新（需要互联网）：

```bash
sudo apt update
sudo apt install -y unzip curl python3-venv python3-pip
```

apt报下载失败先查时间、DNS和网络；不要把关闭证书校验当作修复。系统提示需要重启时，先完成文件保存再`sudo reboot`，稍后重新SSH登录。不强制在比赛前临时进行整套系统大升级。

## 6. 电脑传文件，树莓派解压

Windows PowerShell另开一个窗口，确认ZIP在Downloads中：

```powershell
scp "$env:USERPROFILE\Downloads\RoomGuard_V2_FullProject.zip" student@192.168.1.103:/home/student/
```

用户名、IP与实际下载位置要改。命令运行结束且无报错才算传输完成。也可用可信SFTP工具传到用户主目录，不需要把项目复制进系统目录。

返回树莓派SSH窗口：

```bash
ls -lh ~/RoomGuard_V2_FullProject.zip
mkdir -p ~/roomguard
unzip -q ~/RoomGuard_V2_FullProject.zip -d ~/roomguard
cd ~/roomguard/roomguard-v2
ls
```

预期看到server、arduino、deploy、hardware、docs、tools等目录。`ls`找不到install.sh时，先用`pwd`确认是否位于项目根目录，不用盲目改文件权限。

## 7. 首次安装服务

只在本比赛专用树莓派上首次执行；若已有部署，不覆盖账号和历史，应使用第16节更新流程。已有其他Mosquitto实例时先检查1883端口和listener配置，避免重复监听。

```bash
cd ~/roomguard/roomguard-v2
sudo bash deploy/install.sh
```

按提示设置至少12位管理员密码，账号admin。脚本会安装依赖，创建专用低权限用户roomguard，生成服务器MQTT账号密码（节点独立凭据在教师批准时发放），安装消息代理、业务服务、自启动与受限校时工具。安装阶段会联网，可能需要数分钟；等待命令明确显示“安装完成”。脚本先检查HTTP就绪，失败时不会假报成功。

路径含义：`/opt/roomguard`是运行代码与Python虚拟环境；`/etc/roomguard`是受保护配置；`/var/lib/roomguard`是数据库。不要手动把任意项目文件移动到这些目录替代安装流程。

验证：

```bash
sudo systemctl status roomguard --no-pager
sudo systemctl status mosquitto --no-pager
curl -s http://127.0.0.1:8080/api/status
```

服务应为active(running)，curl应返回JSON。初次尚未烧录节点时online=false正常；broker_online应在启动连接后为true。网页密码与Linux登录密码、Wi-Fi密码、MQTT密码是不同用途，不要求相同。

若失败：

```bash
sudo journalctl -u roomguard -n 80 --no-pager
sudo journalctl -u mosquitto -n 80 --no-pager
```

看到Python模块缺失查pip安装；1883占用查重复代理；Permission denied查配置文件和运行用户权限，不使用chmod777；不删除数据库来碰运气。

## 8. 固定服务器地址

优先在MW305R可用的DHCP地址保留／静态分配功能中，将树莓派网卡MAC与已规划IP绑定；不同固件菜单名称不同，不能保证截图版本一定支持。使用有线时绑定有线MAC，换成无线后MAC不同。

可用`ip -br link`查看网卡，`hostname -I`看地址。固件不支持地址保留时，可在NetworkManager为实际连接规划静态IPv4；必须避开DHCP地址池和已有设备，知道网关与DNS后再做。远程改IP会中断SSH，建议在有本地控制台或备用连接时执行，不在不了解网段时照抄静态IP命令。

比赛部署确定后，记录“树莓派IP、连接方式、MAC、路由器网段”。原截图192.168.1.103仅为示例，不直接写死到所有现场。

## 9. 电脑浏览器验收服务

打开`http://实际树莓派IP:8080/`。首次新装应能打开监控页面，接入前节点列表为空；不是预置101、102。点管理员登录，输入安装时设置的admin密码，按下一节接入两个节点后才出现对应房间。大屏访问`http://实际树莓派IP:8080/?screen=1`，只读、不提供管理按钮。

大屏、PC、平板、手机接同一局域网。若手机关Wi-Fi只用移动数据，局域网地址通常不可达。浏览器先点“启用声音”测试；动画可关闭，不影响采集和告警。实时曲线只积累当前页面收到的有效采样，历史数据在历史页查看。

若Pi本机curl正常但电脑无法访问，检查电脑／手机网段、路由器隔离、防火墙和8080端口；不要通过开放公网端口解决同局域网问题。

## 10. 教师后台接入节点（不再手填MQTT密码）

浏览器打开http://实际树莓派IP:8080/teacher，用教师账号登录。首次账号admin，密码是安装时自己设置的密码，不是Linux登录密码。

首次安装没有固定节点，列表为空是正常现象。生成10分钟接入码，将码交给正在给一台ESP配网的同学；手机连接该ESP热点，填写Wi-Fi、树莓派IP和接入码。节点出现待批准后，教师核对设备编号，绑定房间／楼层并批准。

MQTT账号由受限系统助手创建并reload代理，成功后才标记批准。设备取得自己的密码，教师无需把服务器MQTT密码分给学生。若助手未安装、权限错误或代理停止，后台会报失败，不能把界面按钮点击当作完成接入。

按《ESP手机配网与Arduino烧录_V2》给两个实际节点操作，可分别绑定101、102。增加第三节点时重复接入步骤，不修改服务器设备常量或网页。DEMO中的第三节点是模拟设备，不说明已采购或装配第三套实物。

## 11. 配置EXE、APK与动态界面

Windows10 x64运行V2.0 EXE，填写服务器HTTP地址。需要系统Edge；图形页面由同一树莓派提供，更新服务器页面后刷新即可获得新界面。

OPPO R7sm安装V2.0开发签名APK，在连接设置填同一地址。后台／锁屏告警需要常驻服务、系统允许后台、自启动与Wi-Fi休眠配置，并做真机测试。断网或被强停后无法保证新告警。网页动画不等于APK后台能力；普通页面在后台可能暂停。

动态内容：数据更新高亮、告警状态闪烁、在线链路、最近最多60个采样的温湿度和MQ相对响应趋势、最后采样年龄。页面默认轮询2秒，节点默认常规上报5秒；教师可分别配置查询与上报周期，不用动画伪装成高频新数据。断线曲线冻结，数据过期提示保留；关闭动画不停止数据刷新。

## 12. 无互联网时的最终检查

断开路由器WAN而保留局域网，验证：节点上报、页面访问、告警、管理员操作、历史与CSV都正常。需要时在管理页用当前电脑／手机时间校时。

树莓派3B若没有RTC，断电后时间可能不准。手动校时会关闭NTP，恢复网络后需要自动校时再执行`sudo timedatectl set-ntp true`。热点仅作备用维护，不让服务器在比赛中自动切走原路由器。

## 13. 日常开机与关机

开机：路由器→树莓派→节点→终端。等服务启动与MQ预热，确认房间状态，再启用终端声音。树莓派服务已设开机自启，通常无需每次手工运行Python。

关机：先停止测试异常并保存数据，树莓派执行`sudo shutdown -h now`，等待系统停止后再断电。不要直接用拔电源代替日常关机。节点和路由器按实际供电要求关闭。

## 14. 每次比赛前的维护检查

一键只读诊断：

```bash
cd /opt/roomguard
sudo /opt/roomguard/venv/bin/python -m tools.doctor --db /var/lib/roomguard/monitor.db
```

它检查服务、Web、代理、磁盘、时间标记、节点在线和数据库quick_check，不输出密码；不能代替万用表量测、真实传感器测试或手机锁屏验证。

常用手工命令：

```bash
hostname -I
df -h
free -h
sudo systemctl is-active roomguard mosquitto
sudo journalctl -u roomguard -n 60 --no-pager
sudo journalctl -u mosquitto -n 60 --no-pager
sudo ss -lntp
```

看日志实时变化用`sudo journalctl -u roomguard -f`，结束按Ctrl+C，不会停止系统服务。排查先读日志、确认网络和供电，不先重装系统。没有故障时不反复重启。磁盘不足先导出、确认保留策略并清理自己确认不需要的备份，不能直接删除正在写入的数据库。

## 15. 备份和恢复

项目自带SQLite一致性备份工具，能包含已提交的WAL内容：

```bash
cd /opt/roomguard
sudo mkdir -p /var/lib/roomguard/backups
sudo chmod 700 /var/lib/roomguard/backups
sudo /opt/roomguard/venv/bin/python -m tools.backup /var/lib/roomguard/monitor.db /var/lib/roomguard/backups/monitor-manual.db
```

同名备份会写入该目标文件，需要保留多份时用不同文件名。备份包含账号哈希和历史，按敏感资料保管；生产配置还需备份/etc/roomguard及Mosquitto账号配置，不把它们放进公共项目包。

恢复前先停服务，保留现有monitor.db、monitor.db-wal、monitor.db-shm作为故障样本，再把“一致性备份”恢复到数据库路径，确保旧WAL/SHM不再与新备份混用。设置owner为roomguard:roomguard、权限600，启动服务后查看日志。此步骤涉及替换数据，新手应由教师监督，不在未备份时操作。

## 16. 更新版本而不丢历史

先将新ZIP解压到新的用户目录，确认版本和文件。不要重新运行首次安装脚本覆盖账号。

```bash
cd ~/roomguard/roomguard-v2
sudo bash deploy/update.sh
```

更新脚本先备份数据库和旧server代码，再停服务、复制新代码和维护工具、安装依赖、启动并检查HTTP。备份位于`/var/lib/roomguard/backups/时间戳/`。若更新失败，会说明备份路径，不假报成功；查日志后可恢复旧server代码。更新期间终端短暂断开，但节点本地监测和报警不依赖服务器。

## 17. 忘记密码与服务恢复

忘记网页admin密码，不删除数据库：

```bash
sudo systemctl stop roomguard
cd /opt/roomguard
sudo /opt/roomguard/venv/bin/python -m tools.reset_admin
sudo systemctl start roomguard
```

工具先备份，再交互重设密码，写审计，不显示密码。Linux用户密码忘记是另一类系统维护问题，不能用网页工具修改。

按需重启服务：`sudo systemctl restart roomguard`或`sudo systemctl restart mosquitto`，执行后观察状态与节点恢复；不要连续重复重启掩盖故障。

## 18. 故障定位顺序

| 现象 | 先检查 | 然后检查 |
| --- | --- | --- |
| SSH进不去 | 电源、卡、IP和同网段 | SSH启用、用户名密码、主机指纹 |
| Pi本机网页不可用 | systemctl和业务日志 | Python依赖、权限、端口占用 |
| Pi本机正常，电脑打不开 | 实际IP、网段、8080 | 路由器隔离、防火墙 |
| MQTT未连接 | mosquitto服务与日志 | 配置文件权限、账号、重复listener |
| 单节点离线 | 该节点电源、2.4GHz、烧录配置 | DEVICE_ID、对应密码、实际服务器地址 |
| 全节点离线 | 路由器、代理与服务器地址 | 是否换了热点／网卡、ACL、路由器隔离 |
| DHT故障 | 3.3V、GND、DATA和上拉 | 引脚、模块方向、线缆 |
| MQ异常／不恢复 | 预热、阈值、电平与气体环境 | AO分压、DO极性、模块本身 |
| 消音无成功回执 | 在线与代理连接 | 当前事件是否变化、指令是否过期 |
| 时间错乱 | 时区、NTP、无RTC重启 | 管理端校时与终端自身时间 |
| APK锁屏不响 | 后台服务、Wi-Fi与音量 | OPPO省电策略、真机权限与网络可达 |

建议保存每次故障的“时间、现象、影响房间、日志片段、修改、复测结果”，脱敏后供学生讲述真实调试案例。系统HTTP/MQTT仅面向可信比赛局域网，不对公网开放；不要在汇报截图中显示密码、token或完整私密配置。


## 19. 从V1.1升级的额外核验

先用旧版工具一致性备份数据库，保存受保护的/etc/roomguard和Mosquitto配置。解压V2到新目录，运行deploy/update.sh；它更新服务、ACL、受限维护助手及其专用目录、sudo规则和systemd配置，不重置现有数据库。

旧设备和历史会迁移为已登记设备；旧固件暂保留原逻辑，不支持新配网和新参数。刷V2后设备使用MAC生成新ID，教师应先停用对应旧设备条目，再给新ID绑定原房间，以避免两个活动设备占用同名房间。旧历史不删除。需要重新回到V1.1时恢复升级前数据库与旧代码，不能用旧程序盲目打开已升级的数据库。

检查命令：

```bash
sudo systemctl cat roomguard
sudo visudo -cf /etc/sudoers.d/roomguard-control
sudo systemctl is-active roomguard mosquitto
sudo ls -ld /run/roomguard-control /var/lib/roomguard-control /var/log/roomguard-control
```

Web业务以非root的roomguard用户运行。受限助手仅接受结构化白名单操作，专用锁／暂存／日志目录由root持有；不要给业务用户写整个/etc，也不要设置chmod777。systemd的写路径白名单只让助手执行必要文件操作，不等于业务用户取得root权限。

## 20. 维护操作与失败恢复

教师后台可以查询和控制roomguard、mosquitto两项服务，配置开机启用、读取脱敏日志、创建备份与受控恢复。后台排队返回不等于操作已完成，真正结果在重连后的维护记录中。业务服务被停止后，网页无法自救，使用SSH执行sudo systemctl start roomguard。

恢复数据库前后台会先创建当前一致性备份；仅允许选择管理目录内已存在的V2备份，输入RESTORE确认。恢复过程检查数据库、短暂停服、替换并重启；MQTT密码文件不自动回滚，需要核对节点连接或重新配网。V1.1备份不能直接从V2网页恢复，应按整套版本回退流程处理。

V2后台临时接入码和发放凭据在受保护数据库中短期保存，10分钟过期后清理；备份文件也需保密。审计日志位于/var/log/roomguard-control/maintenance.jsonl。系统崩溃、网络不可达、底层服务损坏时，仍保留SSH／本地控制台和一致性备份恢复路线。

旧APK签名不保证能直接覆盖安装V2开发测试版。本次使用新开发测试签名，必要时先卸载旧版再安装，并重新设置服务器与后台运行许可；不随项目公开签名私钥。
