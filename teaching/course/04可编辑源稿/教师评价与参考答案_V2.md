# RoomGuard V2 教师评价与参考答案

教师使用。学生先独立预测、操作和作答，再按本资料讨论；不要直接把答案当背诵稿。本建议属于教学评价，不代替具体比赛评分细则。与《教师项目化教学指导手册》《学生学习与实操任务单》配套。

## 一、学前诊断：先看学生起点，不计入结课总分

分别请两人完成下列任务，记录“独立完成／提示后完成／未完成”，不由同伴代答。

| 项目 | 教师观察内容 | 后续补学 |
| --- | --- | --- |
| 文件操作 | 能找到ZIP、解压并说出路径 | 用资源管理器与pwd／ls对照 |
| 接口识别 | 能指出VCC、GND与USB数据接口 | 实物标识与断电查线 |
| 电压概念 | 区分供电电压和GPIO信号 | 电源／信号两张图 |
| 网络概念 | 知道Wi-Fi名与IP不同 | 画局域网，查设备列表 |
| 编程基础 | 找到setup／loop并说明作用 | 从入口和调用顺序入门 |
| 读错误信息 | 愿意保留报错而非关闭窗口 | 故障记录模板演练 |
| 口头表达 | 能用30秒说明一个操作 | 使用“动作—观察—判断”句式 |
| 合作记录 | 操作前提醒同伴，记录实际结果 | 明确操作者／核查者轮换 |

如果两人都未接触Linux，可在任务5前增加2学时窗口与目录训练；电路基础弱，在任务2增加2—4学时测量练习。网络依赖未就绪，不让学生用整节课反复点安装。

## 三、原理问答：让学生用自己的话解释

1. 为什么用有源蜂鸣器？——内部有振荡源，通断控制适合明确告警；本项目所用模块低电平触发。不能由“有源”推断所有模块都低触发，也不能把GPIO直接当大电流电源。
2. AO和DO分别做什么？——AO读连续变化用于相对响应趋势；DO经比较器按电位器阈值输出开关状态，用作触发判断。当前固件烟雾判定取MQ DO，不是后台随意修改AO数值阈值。
3. DHT11的DO是开关信号吗？——不是本项目所说的普通开关量；它通过有时序的数字协议传温湿度数据，需要相应库。
4. 火焰模块是不是完整消防探测器？——不是，实验模块对特定光谱敏感，受方向、距离与环境光影响；本项目为教学演示原型，不能代替合规消防设施。
5. 为什么MQ-2不能随意接3.3V供电解决电平？——其加热与模块电路有供电要求；应按器件规格供电并适配信号，不用错误供电换取“电压看起来低”。
6. 为什么上位机可以消音却不能认为异常已消失？——消音是处置动作，异常是否消失由传感器与稳定判定决定，二者意义不同。
7. 短暂正常1秒为什么仍报警？——要避免输入抖动和反复鸣停；必须全部原因正常并连续满足设定稳定时间。
8. 服务器校时为什么不应改变离线等待？——离线计时使用单调时钟，与显示用的日历时间分开，避免校时跳变导致误判。
9. ESP32与ESP8266能共用一个BIN吗？——不能。芯片架构、启动和驱动不同；公共业务源码可复用，同型号设备可烧同型号通用固件。
10. AP配网是不是OTA？——不是。前者改变Wi-Fi、Pi地址与接入信息，后者是无线更新固件，本版没有OTA。
11. 十分钟接入码如何使用？——教师生成，绑定一台设备的接入申请；批准并创建独立MQTT凭据后才获准连接。过期需新码，不能拿同一码无限新增。
12. 身份固定就能防硬件冒充吗？——不能。MAC派生ID只是稳定标识，不是硬件认证；教师仍要核对实际设备，本版面向可信局域网且未提供TLS。
13. 每个终端是否都要独立添加新房间？——不需要。它们从服务器动态获取设备与显示方案；但教师审批和范围筛选条件仍必须满足。
14. 新增任意传感器能自动驱动吗？——不能。自适应节点清单不等于自动生成新传感器驱动；还需能力定义、硬件、固件、校验和界面支持。
15. 大屏只读是否意味着数据完全保密？——不是。公开状态用于可信LAN展示；终端过滤不是网络保密边界。学生操作权限与显示过滤要分清。
16. 节点离线后最后一次异常如何处理？——标离线和数据过期，保留最后已知异常，不能静默回到绿色正常，也不能伪造新样本。
17. MQ预热完成是否表示空气安全？——不是；预热是设备状态，数值还受器件稳定、阈值与环境影响。
18. DHT故障会不会关闭烟火报警？——不应。温湿度采集与烟火告警分开；故障要显示，不能用0代替有效温湿度。
19. 停用节点会关闭本地报警吗？——不会。服务器撤销后续凭据并拒收遥测，不等于切断节点电源或停止本地逻辑。
20. 断网后是否补齐全部历史？——本版重连上报当前状态，不保证补传所有断网样本和事件，汇报时应说明。
21. EXE是否独立离线运行整套系统？——不是。它通过系统Edge打开Pi界面，仍需服务器可达，关闭后不提供独立后台声音服务。
22. APK兼容API22是否保证OPPO锁屏一定响？——不保证。还需实际网络、音量、后台／省电策略与真机验证；强停或断网时不能保证新告警。
23. 没有RTC且比赛无互联网怎么办？——开机核对时间，可从教师网页／上位机校时；校时来源也须正确，并保留重启与时间验证。
24. 我们解决了什么、效益怎样表达？——减少分散信息难以持续查看的问题，提供房间定位、就近提醒、处理记录和教学运维入口；没有实证就不写事故降低百分比或大规模部署成效。

## 四、四道计算与状态推演

题1：输入5V，上电阻20kΩ、下电阻10kΩ，理想输出是多少？

参考：5×10/(20+10)=1.667V。这里只是理想分压；还要核对输入上限、电阻误差、ADC量程和模块负载。不能据此宣布未知ESP8266板A0一定安全。

题2：ESP8266参考上56kΩ、下10kΩ，理想5V输出？若A0连接器满量程实际3.2V，为什么不能直接当裸芯片1V或所有板都3.2V？

参考：5×10/(56+10)=0.758V。板载分压可能不同，软件满量程参数必须与手中开发板实测相符；满量程错误会使换算失真。不要绕过量程核验只改软件比例。

题3：实际生效上报周期分别为5、10、60秒，服务器离线门限约为多少？

参考：max(20秒，4×实际生效周期)，分别约20、40、240秒。课堂观察有轮询与调度延迟，记录实际值及条件；按“有效消息”而非任意报文恢复在线。

题4：解除稳定时间10秒，0秒烟雾触发，5秒全部正常，12秒再次烟雾，15秒全部正常，20秒与25秒分别是什么状态？

参考：5—12秒正常仅持续7秒，不能解除；12秒打断稳定等待；15秒重新开始计时。20秒只有5秒正常仍报警；约25秒满足10秒稳定后解除，终端显示还受消息与查询延迟影响。

## 五、故障情境与指导追问

| 情境 | 首先让学生做什么 | 参考定位与验收 |
| --- | --- | --- |
| 编译失败找不到库 | 保留错误首段，核对核心与Sketchbook | 查随包libraries及版本，修复后重新验证；不是先换芯片BIN |
| 电脑找不到端口 | 核对数据线、设备管理器和驱动 | 换已确认数据线、记录实际COM；不要随意短接引脚 |
| 单节点离线 | 查该节点供电、Wi-Fi、ID和最后状态 | 对照服务器位置绑定，避免误停另一台；重连后看有效上报 |
| 全节点离线但页面可开 | 先看代理状态、路由器与Pi地址 | 检查mosquitto、凭据／ACL和网络，不先同时重刷两板 |
| 网页仍绿但不更新 | 看连接提示和最后更新时间 | 查服务器可达、数据过期；静态绿色不能证明安全 |
| DHT显示故障 | 看接线、供电、DATA脚和上拉 | 断电修复后看有效读数；不删故障或填0掩盖 |
| 消音按钮后仍响 | 核对在线、当前事件、新原因和回执 | 新原因重新鸣叫可属正确行为；不能一律判通信故障 |
| APK前台响、锁屏不响 | 记录手机系统、网络和后台设置 | 做受控锁屏复测；不以电脑浏览器通过代替 |
| 新节点申请未出现 | 分开查ESP联网、Pi地址、接入码、HTTP | 待批准不是在线；先核对串口ID，不盲目批准陌生ID |
| 改了参数却旧值 | 比较期望、实际、同步状态与消息链路 | 离线期望可保留；以实际应用确认，不重复狂点保存 |
| 业务服务停止后后台打不开 | 检查是否正是预期影响 | SSH启动roomguard，再核对日志与节点；不反复改浏览器地址 |
| Pi重启日期不准 | 核对RTC／NTP／离线环境 | 正确来源校时并检查记录；不能用错误系统时间做响应统计 |

## 六、个人评价量规：满分100分

每人单独填写。按对应表现与证据给分：L4可独立诊断迁移，通常取该项90%—100%；L3独立完成并解释，75%—89%；L2需清单或多次提示，50%—74%；L1仅能指认，低于50%。这是教学参考区间，教师可按具体表现调整并说明理由。

## 七、结课实操抽测：两人都要做

建议课后另安排40—60分钟补测；课内只抽核心操作，等待预热、下载和30分钟锁屏测试单列。设备预先保持已核验状态，教师只改变可恢复条件。

1. 随机给一块板，学生说出型号、对应工程、端口与一次上传前检查。
2. 从已知局域网找到Pi地址并SSH登录，用一条命令说明服务状态，不读出密码。
3. 指定房间，核对ID与绑定；说明若新增同型号节点如何接入，教师批准由教师完成。
4. 指定一个已批准的受控异常场景，先预测，再观察声光与网页，完成确认与本次消音并解释区别。
5. 指出一条当前数据的时间和有效性，查到相关历史，保存一份脱敏CSV。
6. 教师给出一项可恢复故障，学生提出检查顺序并获取至少两条证据，修复后复测。

每步记录独立程度、准确性和证据。A与B轮换，另一人只记录、不代按按钮或代答。教师可以允许查手册，重点考理解、定位与操作，不考机械背命令。
