# RoomGuard V2 课堂知识与操作速查卡

供学生带到操作台。示例IP和用户名必须替换为实际值；密码不写在卡上。首次操作仍按完整手册，不把速查卡当作未经核验接线的授权。

## 卡1：一句话讲清系统

房间节点采集温湿度、烟雾与火焰；节点独立判断烟火异常并驱动声光；路由器转发数据；树莓派保存、处理和提供网页；电脑、手机与大屏查看状态并按权限处置。

温湿度只展示；烟雾或火焰任一触发该房间报警；同时触发显示两个原因。确认是已阅，消音是当前蜂鸣停止，全部原因正常并稳定N秒才解除。节点断网时仍需供电，本地报警继续；中心标离线、保留最后异常。

## 卡2：五模块与易混词

| 名称 | 在本项目中的作用 | 不要混淆 |
| --- | --- | --- |
| DHT11 | 温湿度数字协议采集 | DATA不是普通开关DO |
| MQ-2 AO | 连续电压，相对响应与趋势 | 未标定不能说准确ppm |
| MQ-2 DO | 跨阈值时的逻辑状态 | 阈值主要由模块电位器设定 |
| 火焰DO | 火焰相关光学输入的开关状态 | 受光源、方向与环境影响 |
| 有源蜂鸣器 | 声音输出，本模块低触发 | GPIO不是模块大电流供电口 |
| RGB | 正常／异常视觉输出 | 核对共阴／共阳及限流 |
| ESP8266 D0 | 板标签，对应GPIO16 | 不是传感器数字输出DO |
| IP | 当前网络地址 | 不是设备唯一ID或房间号 |
| MQTT | 节点与服务器的消息通信 | 不是浏览器网页本身 |
| AP配网 | 手机填写运行时网络配置 | 不是OTA刷固件 |

## 卡3：输入与处置推演

| 烟雾 | 火焰 | 预期 |
| --- | --- | --- |
| 无 | 无 | 无历史未解除事件且设备就绪时正常 |
| 有 | 无 | 报烟雾原因，该房间声光 |
| 无 | 有 | 报火焰原因，该房间声光 |
| 有 | 有 | 同时保留两原因，该房间声光 |

正常输入不一定立刻解除已有告警，还要等待稳定时间。消音后新增原因或新事件重新鸣叫；离线不能远程可靠消音；已发送不等于已生效。

默认上报5秒、约20秒未收到有效消息离线；上报周期改为已生效10秒时约40秒。默认解除稳定10秒，均以当前节点实际参数为准。

## 卡4：Arduino烧录前六查

□板型：ESP32 Dev Module或NodeMCU1.0（ESP-12E Module）
□核心：ESP32 2.0.17；ESP8266 3.1.2
□工程：arduino/RoomGuard_ESP32或RoomGuard_ESP8266
□库：Sketchbook指向arduino，随包libraries可识别
□供电：从基板取下，仅USB数据线，避免USB与外部电源并联
□端口：设备管理器核对真实COM；串口115200

先验证→再上传→复位观察设备ID／AP信息→按配网步骤上线→再做实物检测。两芯片不能互刷BIN，编译不证明气体或火焰已经检测通过。

## 卡5：Windows与Pi命令位置

Windows PowerShell，先把示例用户名与IP换成自己的：

```powershell
ssh student@192.168.1.103
```

已登录Pi的SSH窗口：

```bash
whoami
hostname
uname -m
pwd
ls
hostname -I
```

依次看用户、主机、架构、当前目录、目录内容和实际地址；64位OS期望aarch64。不是在Windows直接运行Pi服务命令。

在Pi检查服务与业务：

```bash
systemctl is-active roomguard mosquitto
curl --fail http://127.0.0.1:8080/api/status
sudo journalctl -u roomguard -n 40 --no-pager
sudo journalctl -u mosquitto -n 40 --no-pager
df -h
```

预期：服务active，HTTP返回JSON，日志可用于定位、磁盘仍有空间。日志出现报错先保留上下文，截图脱敏。首次安装按完整手册；不要在已有实例反复执行install.sh。

需要持续看业务日志：

```bash
sudo journalctl -u roomguard -f
```

按Ctrl+C只退出日志观察，不会停止服务。教师监督恢复业务服务可用`sudo systemctl start roomguard`。正常关机用`sudo shutdown -h now`，待停止后再断电。

## 卡6：手机配网八步

1. 教师生成10分钟单设备接入码，核对本次要配置的板卡。
2. 通过115200串口私下获取ESP热点SSID与随机密码。
3. 手机连ESP的RG-CONFIG热点，选择保持无互联网连接。
4. 浏览器打开http://192.168.4.1，填写比赛Wi-Fi、Pi IPv4和接入码。
5. 首次ESP8266初始化由教师确认；普通掉网不格式化。
6. 提交后手机切回比赛Wi-Fi，教师核对ID、绑定房间并批准。
7. 观察获批、MQTT上线、热点关闭和房间自动出现；待批准不是在线。
8. 复位／重启验证配置保存；仍按完整手册复核供电与电平。

运行后需要重配时，按烧录手册长按BOOT／FLASH约5秒；不是上电时一直按住使板卡进入下载模式。不要公开热点密码或服务器凭据。

## 卡7：终端与历史

工作台：http://实际Pi地址:8080/

大屏：http://实际Pi地址:8080/?screen=1

教师：http://实际Pi地址:8080/teacher

Windows EXE使用系统Edge；APK设置同一Pi服务器。192.168.4.1只用于ESP配网，不是Pi长期地址。网页启用声音需本机点击，APK后台需系统许可与网络；两者分别验收。

历史查询先选房间／设备与时间，核对发生、确认、恢复记录；CSV一次最多10000条，需要时分时段导出。默认采样保留30天、事件与审计180天，教师可调整。

## 卡8：排障五句话

“什么现象，什么时候开始？”

“只有一个房间，还是全部终端／节点？”

“我准备先查哪一层，预期看到什么？”

“证据支持哪个原因，我只改了什么？”

“同一场景复测通过了吗，还有什么未验证？”

单节点先查该节点供电与连接；全节点查公共网络、代理与地址；Pi本机可开而终端不可开，查网段／隔离／防火墙；窗口有旧数据时看更新时间，不把绿色当作持续安全。

证据标记：SIM=模拟，INJ=受控测试输入，PHY=实物检测；不能互相替代。对不确定问题，准确说“待验证，计划检查____”，不编造结论。
